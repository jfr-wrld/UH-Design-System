# Radio

One option selected out of a small, fully-visible set - a room-sharing tier,
a payment plan. A `Radio` is never used alone: it needs at least one sibling
sharing the same `value`-space to mean anything, so in practice it is always
rendered inside a `RadioGroup`, which owns the shared `name`, the selected
`value`, and the group's `disabled`/`error` state and hands them down through
context. `RadioGroup` is a `<fieldset>` with a `<legend>`, so the group is
named natively - `role="radiogroup"` is layered on only to carry
`aria-orientation`, which a plain fieldset has no way to express. Arrow-key
navigation and the single tab stop are not reimplemented; they are the
browser's own behaviour for native radios that share a `name`.

## Props

Tabel di bawah adalah props `Radio` itu sendiri - satu opsi di dalam grup.
Untuk props level grup (`name`, `value`, `orientation`, `required`,
`disabled` menyeluruh, `helperText`/`errorMessage`), lihat `RadioGroup`,
yang dikirim turun ke tiap `Radio` lewat context dan bisa ditimpa per-opsi
(lihat contoh `OptionDisabled` di bawah, yang menonaktifkan satu opsi saja).

## Aksesibilitas

**Peran ARIA:** `Radio` sendiri tidak menambah peran - `<input type="radio">`
native sudah membawa role `radio`. `RadioGroup` menambahkan
`role="radiogroup"` di atas `<fieldset>`, semata untuk membawa
`aria-orientation`; nama grupnya tetap berasal dari `<legend>` native, bukan
dari `aria-label`.

**Catatan screen reader:**

- Label diklik lewat elemen `<label>` yang di-`htmlFor` ke id input, jadi
  mengklik teks label atau `description` opsi sama efeknya dengan mengklik
  boksnya.
- `description` per opsi ditautkan lewat `aria-describedby` ke input radio
  itu sendiri, bukan ke grup - jadi tiap opsi punya penjelasannya sendiri
  yang terbaca setelah namanya.
- `RadioGroup` yang punya `errorMessage` menautkan pesan itu lewat
  `aria-describedby` di fieldset dan merendernya dengan `role="alert"`,
  supaya screen reader mengumumkannya begitu grup difokus atau pesannya
  muncul.
- Boks glyph visual (dot) selalu `aria-hidden` - dia murni mencerminkan
  state input lewat CSS, sehingga screen reader membaca input aslinya, tidak
  pernah boksnya.

**Wajib disediakan konsumen:**

- `label` dan `value` pada tiap `Radio` - keduanya wajib secara tipe
  TypeScript; `value` adalah apa yang dibaca `RadioGroup` untuk menentukan
  opsi mana yang cocok dengan `value`/`defaultValue`-nya.
- `label` pada `RadioGroup` - jadi teks `<legend>`, wajib karena grup tanpa
  nama tidak menyampaikan konteks "pilih satu dari apa" ke screen reader.
- Kalau `Radio` dipakai berdiri sendiri di luar `RadioGroup`, pemanggil
  wajib menyediakan sendiri `name`, `checked`, dan `onChange` - di luar
  konteks grup, `Radio` tidak tahu radio lain mana yang perlu dinonaktifkan
  saat dirinya dipilih.
