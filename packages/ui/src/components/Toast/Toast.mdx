# Toast

Feedback yang tidak dibuka, melainkan diumumkan. `ToastProvider` memasang
satu stack ke `document.body` hanya selagi ada toast aktif; `useToast()`
mengembalikan `show`/`success`/`warning`/`error`/`info`, masing-masing
menaruh satu record ke stack yang sama. Ini satu-satunya overlay di sistem
ini yang tidak punya `open`/`onClose` - siklus hidupnya sepenuhnya dikelola
lewat pemanggilan fungsi dan timer auto-dismiss-nya sendiri.

## Anatomi

Root-nya diportalkan ke `document.body` hanya saat ada toast aktif.

- **`.uh-toast-viewport`** - kontainer stack; `data-position` menentukan sudut (`top-center`/`top-right`/`bottom-center`/`bottom-right`) dan arah tumpukan.
- **`.uh-toast`** - satu item; `data-state` (open/closing/closed lewat `usePresence`, sama seperti Modal dan BottomSheet) dan `data-variant`.
- **`.uh-toast__icon`** - ikon status, hanya render untuk `success`/`warning`/`error`/`info` - `default` tidak punya ikon.
- **`.uh-toast__body`** - pembungkus `title` + `description` + `action`.
- **`.uh-toast__title`** - opsional, baris pertama yang lebih tebal.
- **`.uh-toast__description`** - satu-satunya field wajib di `ToastOptions`.
- **`.uh-toast__action`** - tombol teks opsional, terpisah dari tombol close; klik-nya tidak menutup toast.
- **`.uh-toast__close`** - berbagi styling dengan `.uh-close-button` bersama (`data-size="sm"`).

## Props

`ToastProvider` sendiri hanya membawa tiga prop:

Permukaan yang sesungguhnya dipakai konsumen adalah `useToast()`, yang
mengembalikan objek ini (dari `useToastContext.ts`):

```ts
interface ToastOptions {
  title?: string;
  description: string; // satu-satunya field wajib
  variant?: 'default' | 'success' | 'warning' | 'error' | 'info';
  duration?: number | null; // ms; null menonaktifkan auto-dismiss
  action?: { label: string; onClick: () => void };
  closeLabel?: string; // accessible name tombol close, default "Dismiss"
}

interface ToastContextValue {
  show: (options: ToastOptions) => { id: string; dismiss: () => void };
  success: (
    description: string,
    options?: Omit<ToastOptions, 'description' | 'variant'>,
  ) => ToastHandle;
  warning: (
    description: string,
    options?: Omit<ToastOptions, 'description' | 'variant'>,
  ) => ToastHandle;
  error: (
    description: string,
    options?: Omit<ToastOptions, 'description' | 'variant'>,
  ) => ToastHandle;
  info: (
    description: string,
    options?: Omit<ToastOptions, 'description' | 'variant'>,
  ) => ToastHandle;
  dismiss: (id: string) => void;
  dismissAll: () => void;
}
```

## Contoh penggunaan

### Konfirmasi berhasil

Shorthand `toast.success(description, { title })` - varian paling umum, hilang sendiri setelah 4 detik.

### Kegagalan yang menunggu keputusan

`toast.error(...)` tidak pernah auto-dismiss kecuali `duration` ditimpa - "Payment failed" yang hilang sendiri adalah cara seseorang kehilangan jejak pembayarannya.

## Aksesibilitas

**Peran ARIA:** item toast sendiri **tidak** membawa `role="status"` atau
`role="alert"`. Ini disengaja - lihat komentar di `Toast.css`: penyisipan
`role` diumumkan secara tidak konsisten antar screen reader, khususnya
Safari + VoiceOver. Sebagai gantinya, `ToastProvider` memanggil `announce()`
dari `lib/announcer.ts`, yang menulis ke live region tersembunyi yang sudah
ada sejak awal (`aria-live="polite"` untuk `default`/`success`/`info`/
`warning`, `aria-live="assertive"` untuk `error`) - dites langsung di
`Toast.test.tsx` ("announces the description through the shared live
region", "announces error toasts assertively").

**Catatan screen reader:**

- Timer auto-dismiss berhenti selama hover **atau** fokus berada di dalam toast, dan baru lanjut lagi setelah _keduanya_ dilepas - bukan begitu salah satu saja lepas (WCAG 2.2.1 Timing Adjustable). Ini dites lewat kasus "hover lalu fokus tombol action lalu lepas fokus": timer tetap tertahan selama pointer masih di atasnya.
- `error` tidak pernah kedaluwarsa sendiri kecuali dipaksa lewat `duration` - seseorang harus benar-benar menutupnya.
- Melebihi `limit` (default 4) menutup toast aktif tertua, bukan memotong toast terbaru dari tampilan - dites di "dismisses the oldest active toast once the limit is exceeded".

**Wajib disediakan konsumen:**

- `<ToastProvider>` di root aplikasi (atau di scope yang relevan) sebelum komponen mana pun memanggil `useToast()` - hook ini melempar error di development jika dipanggil di luar provider: `"useToast must be used within a ToastProvider."`
- `description` - satu-satunya field wajib di `ToastOptions`; `title` dan sisanya opsional.
- `closeLabel` untuk melokalkan nama aksesibel tombol close saat bahasa aplikasinya bukan Inggris.

## Catatan i18n

Deskripsi Melayu dan Indonesia berjalan lebih panjang dari Inggris untuk
pesan yang sama; kartu toast melebar ke bawah (wrap) dan tidak pernah
memotong teks, sementara lebarnya tetap dibatasi oleh token
`size.toast.width`. Story `TextExpansion` menonaktifkan `duration` lewat
`null` supaya ketiga bahasa bisa berdiri berdampingan untuk dibandingkan -
dalam pemakaian nyata, kontennya tetap kedaluwarsa (atau tidak) mengikuti
aturan durasi yang sama untuk setiap bahasa:
